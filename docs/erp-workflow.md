# 商品加工与妙手回传

默认“设置 → 采集路线”选择妙手接口；插件本机接收为备用。三条来源复用商品编辑、AI、保存审核及回传服务。“商品加工”区分获取方式和货源平台，“采集记录”切换接口或插件历史，“回传记录”独立查询原因和只读核对，“操作帮助”可跳转各阶段。

接口导入逐条保存到 `miaoshou_import_records`，记录批次、账号、目标、商品、结果和详情；成功、重复、失败都可追溯。重复导入保留加工内容。旧版导入从保留的首次快照展示历史，不伪造旧任务记录。

发送前检查失败同样记录“未发送”，并提供进入加工或查看回传记录入口。实际回传依次提示检查、读取最新原商品、准备图片、提交商品及保存回执。商品列区分未传、未发送、回传中、已传、需重传、失败和待核对，只有当前账号及内容匹配成功回执才显示已传。

## 直接从妙手导入

商品加工的“同步妙手采集箱”调用公共采集箱列表和详情接口。查询结果可按货源商品 ID 过滤，勾选后读取完整详情并保存到本机商品加工列表。导入身份使用“AppKey 账号 + 妙手公共采集箱商品 ID”，同一身份重复导入只返回本机已有版本，不覆盖手动或 AI 修改。

API 导入商品会保存原商品 ID、完整远端详情快照、稳定的 SKU 组合键、全部货源/认证/规格和未展示字段。导入时的 `ossMd5` 不作为后续更新凭据；更新前重新读取最新详情和 `ossMd5`。商品编辑器和 AI 入口与插件采集商品共用；标题、简易描述、图文详情、主图和可支持的既有两维 SKU 修改后保存，再按“新增加工副本”或“更新原商品”回传。更新仅合并本机实际修改字段；新增副本以首次导入详情和固定导入基线合并全部加工字段，不丢失第三规格和远端附件，即使之前已成功更新过原商品。

API 原商品保存审核和更新时，未编辑的空编号、空售价、零重量/尺寸等保留原值，不要求为只改标题补齐全部数据；实际修改过的字段仍校验。新建副本仍检查完整性。原始完整详情可从商品行“更多 → 查看妙手导入原始详情”查看；重复导入不会刷新覆盖本机已有编辑。

插件转发和 JSON/HAR 文件导入仍然保留，适合需要自行解析、扩展字段或在妙手接口不可用时使用。两条路线进入同一个商品编辑、AI、审核和回传流程；来源平台商品 ID 不代替妙手商品 ID。API 路线不需要重装或重新加载浏览器插件。

## 实际操作

1. 源码运行时重启 `python main.py`；可执行版需自行重新打包后双击新的 `BeadDiff.exe`。进入“设置 → 妙手 ERP”，填写妙手开放平台分配的 **AppKey、AppSecret**，点击“保存凭证与汇率”。Apifox 文档密码不能用于调用接口。
2. 若销售价/货源价不是人民币，填写人工确认的汇率，每行形如 `USD=7.20`，表示 1 USD 对应 7.20 CNY。此处数值仅作格式示例，软件不会自动填写。CNY 固定为 1；未配置的币种阻止发送。保存后点击“测试连接（只读）”。
3. 点击商品加工“同步妙手采集箱”，查询并勾选商品后导入，或直接填写妙手商品 ID 导入。API 商品自动关联到原商品。选择并保存回传方式：默认“新增”创建加工副本；“更新”修改原采集商品。插件路线选“更新”时，仍需在商品行“更多”点击“关联妙手原商品”，读取详情并核对标题/链接/站点后确认关联。关键词结果不等于精确匹配，平台来源 ID 不等于 ERP ID。
4. 编辑商品并保存/审核。在“货源链接”栏目可填写独立“回传货源价”，币种与商品当前币种一致。**新增商品（包括多 SKU）必须有商品级货源价**；有 SKU 销售价不代表有货源价，软件不会用销售金额或最低 SKU 价格代填。API 导入商品会读取妙手已有的商品级货源价。
5. 商品行“更多”可单条回传，勾选商品可批量回传；辅助字段从“显示列”展开。“回传记录”显示冻结版本、操作方式、目标 ID、实际脱敏响应及失败原因。**当前写入的是公共采集箱**；认领到渠道采集箱、审核和发布仍在妙手操作。

## 凭证与鉴权

凭证文件是 `data/miaoshou.local.json`（设置了 `BEADDIFF_DATA_DIR` 时跟随该目录），与插件接收密钥、AI 模型文件分开。启动时读取并显示已有配置，支持编辑保存、重载及清空凭证。文件及原子保存的临时文件被 `*.local.json` / `*.local.json.*` 忽略；缺失文件不会在启动时自动创建，首次保存时创建。凭证在本机明文存储，界面 AppSecret 遮挡显示；回传日志不保存密钥或请求签名。外部修改/无效 JSON 会阻止覆盖，需先重载/修复。

只调用官方固定地址 `https://openapi-erp.91miaoshou.com`，不复用浏览器登录 Cookie 或采集提交接口。POST JSON 请求头是 `x-app-key`、秒级 `x-timestamp`、`x-sign`，签名为：

```text
HMAC-SHA256(appSecret, appSecret + path + timestamp + appKey + bodyJson + appSecret)
```

签名使用小写十六进制；签名和发送使用同一份 UTF-8 JSON 字节。电脑时间、接口权限、AppKey/AppSecret 和账号 IP 白名单都可能影响调用。测试连接只调用列表查询，不证明新增、更新、图片权限已经获批。

## 更新与数据保护

新增调用 `/open/v1/product/common_collect_box/common_collect_box/add_common_collect_box_detail`，产品对象直接作为请求体。

更新先调用 `get_common_collect_box_detail`，获取新鲜的 `editCommonCollectBoxDetail` 和必需 `ossMd5`，再调用同目录下的 `edit_common_collect_box_detail`：

```json
{
  "commonCollectBoxDetailId": 123,
  "editCommonCollectBoxDetail": {"title": "示例：实际会保留其他允许编辑的远端字段"},
  "ossMd5": "来自本次详情读取的值"
}
```

`ossMd5` 是文档要求的字段；不假定它已经证明乐观锁或版本控制。服务器只读字段（`commonCollectBoxDetailId`、`cateList`、`sourceMataInfo`、`sourceSupplierInfo`）不混入可编辑对象。

首次关联前已经保存的手动/AI 改动不会丢失，首次更新使用已有编辑标记。每次成功更新后，以**当时发送的快照**记录增量基线；下次不会重发旧标题/旧售价去覆盖妙手后来修改的值。远端未编辑的售价、货源价、原价、库存、颜色套图、附件、来源信息保持原值。详情图单独修改时保留远端正文和样式。关联及成功回执绑定 AppKey 指纹；更换账号必须重新关联，“已传”显示也按当前账号判断。

SKU 使用首次采集规格核对远端规格名和组合键；无法唯一匹配时阻止该 SKU 的修改，不猜 ID。当前更新支持**既有规格**的编号、售价、库存、物流和规格图，不支持规格维度/组合增删重构，请先在妙手处理。关联后远端规格名称发生变化也会阻止回传。多个认证附件不能被本机单附件入口覆盖。数值字段清空没有明确契约，不能用省略字段冒充已清空；无库存请填 `0`，重量/售价需填写有效数值。

网络错误会区分连接超时、等待响应超时、发送超时、连接池超时、代理连接失败和连接失败，并记录异常类名、配置超时秒数及是否检测到代理配置，不记录代理地址或原始异常敏感文本。HTTPX 默认读取系统/环境代理，Windows 系统代理也可能被使用；检测到代理不等于已经确认 VPN 是错误原因。可在相同超时配置下，对比开启/关闭代理时的“测试连接（只读）”；只读测试成功只证明查询可达，不证明图片转存一定成功。查询正常但图片等待响应超时时，可将请求超时调到 90～120 秒并点击“保存凭证与汇率”。本次不更改系统代理、VPN 或已保存的超时设置，不增加商品保存的自动重试。

本版不直接保存 Temu 全托管采集箱，不自动执行认领或平台发布。公共采集箱回传成功与商品已经发布是两个状态。API 导入读取的是公共采集箱，更新/新增也写回公共采集箱；认领渠道采集箱、审核和发布仍在妙手完成。

## 成功、失败与未知结果

只有官方成功响应且返回新增 `commonCollectBoxDetailId` 或更新 `ossMd5` 后，才标记相应发送快照“已传”。修改后再次保存不同内容，新内容显示“需重传”；回传期间的新编辑也不会被旧回执标成已传。“已修改”保留曾保存实际改动的状态，AI 应用及本机保存均不等于 ERP 回传。

明确的签名/权限拒绝记为失败；详情查询、字段映射、图片准备失败不会当作可能已保存商品的未知结果。商品保存请求超时、响应缺少必要信息、无法识别的错误或进程中断保留“结果未知”，阻止直接再次发送，尤其不能自动重试新增。

对保存了实际提交内容的未知记录，可在妙手核对来源、标题和时间，找到确切目标 ID，然后点击“核对未知回传（只读）”。程序只读详情，要求原发送账号及目标正确、提交字段全部与远端一致才确认成功；不一致继续保持未知。服务器格式规范化也可能导致严格核对不通过，这时不会强制标成功。旧记录没有实际提交内容时不提供随意清除未知状态的入口。
